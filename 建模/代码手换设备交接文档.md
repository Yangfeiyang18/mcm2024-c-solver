## 1. 接手后先遵守的最新口径

以下内容以建模手最新同步为准，优先级高于旧文档中的冲突表述：

1. 原始 Excel 只读，所有输出写到项目内的新文件，不覆盖原始附件。
2. 固定随机种子为 `seed=2024`。
3. 问题2不叫传统“训练集/测试集”：
   - 100个**优化情景**用于求解方案；
   - 2000个**样本外测试情景**只用于最终独立评价；
   - 2000个测试情景不得参与求解、调参、风险权重选择或方案挑选。
4. 风险权重及最终候选方案必须在查看2000个测试情景结果以前确定。测试结果出来后不得据此返回调整 `lambda`。
5. 以下口径现已锁定，不再等待老师确认，也不要在本轮自行更换：销量按“作物—季次”汇总；三年豆类按滚动三年累计豆类面积不少于地块面积；露天耕地和水浇地最小种植面积5亩、大棚最小0.3亩；每种作物每年每季最多进入7块地。
6. 当前问题2采用 `waste_no_revenue`，即超额产量不计收入。这是因为问题2没有重新明确半价政策而采用的保守假设，必须在论文中说明，本轮保持不变。
7. 问题2最终风险权重已在查看2000个测试情景结果前预先锁定为 `lambda=0.25`。选择理由是它代表期望收益与尾部风险之间的中间折中，而且当前三个风险权重得到的种植结构完全相同。2000个测试情景只验证该方案的样本外表现，不得据此改选风险权重。
7. 智慧大棚第一季参数并非缺失：附件2明确规定其亩产量、成本和价格与普通大棚第一季相同。正确来源标签应为：

   ```text
   specified_same_as_ordinary_greenhouse_first_season
   ```

   不应写成 `fallback`，也不应作为数据警告。这个修正只改来源说明，不改变任何数值，因此不需要重跑问题1优化。

## 4. 新设备环境与运行方法

已用环境：

- Windows + PowerShell
- Python 3.12.13
- NumPy 2.3.5
- HiGHS / `highspy` 1.15.1

建议在新设备安装Python 3.12，并在项目根目录创建虚拟环境：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install numpy==2.3.5 highspy==1.15.1
```

验证求解器：

```powershell
.\.venv\Scripts\python.exe .\src\models\test_highs.py
```

现有Python程序均用脚本位置自动推导项目根目录，因此整个 `03_2024年C题` 文件夹可以放在新设备的任意路径，不依赖本机E盘绝对路径。

常用命令（均从项目根目录执行）：

```powershell
# 仅在固定情景文件丢失时才重新生成；正常交接不要运行
.\.venv\Scripts\python.exe .\src\data\generate_q2_scenarios.py

# 求解候选；会覆盖同名results文件，运行前先备份
.\.venv\Scripts\python.exe .\src\models\solve_q2.py mean_value
.\.venv\Scripts\python.exe .\src\models\solve_q2.py lambda_0
.\.venv\Scripts\python.exe .\src\models\solve_q2.py lambda_025
.\.venv\Scripts\python.exe .\src\models\solve_q2.py lambda_050

# 独立审计
.\.venv\Scripts\python.exe .\src\evaluation\audit_q2.py mean_value
.\.venv\Scripts\python.exe .\src\evaluation\audit_q2.py lambda_0
.\.venv\Scripts\python.exe .\src\evaluation\audit_q2.py lambda_025
.\.venv\Scripts\python.exe .\src\evaluation\audit_q2.py lambda_050
```

注意：`solve_q2.py` 会把本地项目下的 `.python_packages` 加入搜索路径，但不要求必须使用该目录；在虚拟环境中安装 `highspy` 和 `numpy` 后也可正常导入。不要把旧电脑的 `.python_packages` 当成跨电脑环境包使用。

清洗程序 `src/data/clean_data.mjs` 使用 Codex 工作区内置的 `@oai/artifact-tool`。如果新设备只继续问题2且直接接收清洗后CSV与现有情景文件，可以暂时不重跑Excel清洗；若要从原始Excel全流程重建，需要在带该依赖的Codex工作区运行，或把清洗程序迁移到公开Excel库后再验证。
